# Agent Note: 404 里点明"前端已更新但服务未重启"

Status: implemented

## Problem

控制台前端由 `src/web/static.ts` **按请求读盘**投递, 所以改完前端
普通刷新即生效; 而 HTTP 路由表在 `createWebApi` 装配时一次性建立, 只有重启进程才会更新.

两者不同步时用户会看到: 新 UI 已经出现, 点它却回 `404 {"error":"未知接口 POST /api/..."}`,
既不知道是接口不存在, 也不知道该做什么(实际要做的就是重启服务).

## Decision

`src/web/routes/index.ts` 的未知路由 404 文案补一句可操作指引:
"若控制台刚刚更新过, 请重启服务: 路由表在启动时装配, 重启后新接口才存在".

只改文案, 不改分流逻辑与状态码(仍是 404, 未登录仍是 401 ----
身份闸门在域分发之前, 所以未登录时看不到这条 404).

## Alternatives considered

- **什么都不做**: 404 文案本身没错, 只是答不了"那我该怎么办". 而这条分支只在
  版本错配时出现, 正是最需要指路的时候. 否决.
- **让路由表热加载(每次请求重建 / 监听文件变化)**: 能根治, 但把网关的静态接线
  变成运行时可变的, 与[路由表是启动即定的契约]相悖(见
  scripts/gates/checks/guard/route-table.ts 对分流的静态对账). 否决.
- **前端探测版本不匹配并提示**: 需要后端暴露"路由表版本 / 装配时间"再让前端比对,
  为一句提示引入一套新的跨端契约. 否决.

## Consequences

- 未登录请求看不到这条提示(身份闸门先返回 401), 这是原有顺序, 未改变.
- 文案是中文, 与该分支既有文案一致.

## Testing

既有分流用例与门禁不受影响(判据只断言状态码与 faceOf 返回值, 不断言文案):
`node scripts/gates/run.ts route-table`. 文案本身由 typecheck 与
`node scripts/gates/checks/code/format.ts` 覆盖(行宽 120).
