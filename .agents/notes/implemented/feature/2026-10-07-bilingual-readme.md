# Agent Note: README 双语 -- 中文为默认, 英文另起一份文件

Status: implemented

## Problem

仓库只有一份中文 `README.md`. 英文读者(以及只看 GitHub 首页的搜索引擎与 AI)拿到的是
一整页中文; 而 README 的定位是"第一眼"文档, 语言不通等于没有这份文档.

用户要求: 支持中文和英文, **默认显示中文**.

## Decision

保留 `README.md` 为**中文**(默认), 新增 `README_EN.md` 为英文, 两份文件顶部各放一行
语言切换(互为往返链接), 章节逐节对应.

- 默认语言不动: 换掉 `README.md` 的内容等于让所有既有链接(issue / 文档 / 外部引用)
 指向另一种语言; 新增文件是可逆的, 替换不是.
- 两份共用同一批资源: 徽章与 4 张截图不复制, 只换文案. 因此截图更新一次两份同时生效.
- 两份的章节名不同(中文"快速开始" vs 英文"Quick start"), 但**节数, 顺序, 被引用的
 15 篇文档与 16 个本地链接完全一致** -- -- 这是"翻译稿没漏东西"的机械判据.
- 顺带把 README 里的全角标点清零: README 不在标点棘轮基线内, 而全角标点会让
 `grep` 定位失效(本仓大量用 grep 排障). 分隔符统一成既有风格 ` . ` 与 ` -- `.
- `scripts/gates/lanes.ts` 的 notes lane 收编 `README_EN.md`: 顶层条目必须被某条 lane
 认领, 否则 lane 门禁判"未登记"(这条判据正是防"新文件悄悄脱离门禁").

## Alternatives considered

- **把 `README.md` 直接改成英文**: 最省事, 但会让既有中文链接与历史 issue 的引用
 全部改换语言, 且与用户的"默认显示中文"相悖. 否决.
- **单一 README 里中英对照并列**: 文档长度翻倍, 两半都变得难读; GitHub 首页首屏
 会被另一半语言占满. 否决.
- **用 `README.zh-CN.md` + `README.md` 英文**: 这是很多国际化项目的做法, 但与用户
 明确的"默认显示中文"相反. 否决.
- **什么都不做**: 英文读者只能读中文页. README 是项目的第一印象, 这一项不能省. 否决.

## Consequences

- 两份文件需要**同时维护**: 改一份忘了另一份会漂移. 缓解办法是把"两份逐节对应"写成
 可机械核对的事实(节数 / 文档引用集合 / 本地链接集合), 本次已逐项核对一致,
 但**没有加门禁**把它固化 -- -- 也就是说漂移目前靠人.
- `README_EN.md` 从被创建那一刻起就受 lane / 格式 / 文档门禁约束(不会成为"没人管的
 文件"), 代价是新增顶层文件必须同步登记 lane.
- 中文版的既有链接与引用一律未变(仍是 `README.md`), 对外零破坏.

## Testing

`node scripts/gates/run.ts` 17 条全过(含 lanes 对 `README_EN.md` 的认领,
style 对两份 README 的标点检查, docs 对端点与路径引用的对账);
`node scripts/gates/run.ts pre-push` 全过; `typecheck` 0 错.

手工核对(本次实测): 两份 README 各 11 节且一一对应; 各引用 15 篇 docs 文档(全部存在);
各 16 个本地链接(0 死链); 两份的引用集合逐项相同.
