# 选类别

类别集合在配置里是封闭的(\`classes\`). 加一个类别是一次刻意的配置改动,外加项目自己 notes \`AGENTS.md\` 里的一行说明 —— 而不是改个文件夹名,因为门禁会拒绝未知目录.

| 类别 | 覆盖什么 |
|---|---|
| \`feature\` | 新的面向用户或面向模型的能力,或者一个非显然的产品选择. |
| \`bug-fix\` | 缺陷修复,或者一次复盘暴露出来的缺口. |
| \`simplification\` | 减少代码、行为或接口面,且不新增能力. |
| \`architecture\` | 关于已上线源码的结构性决策:模块之间如何关联,运行时的词汇是什么. |
| \`process\` | 代码之外的工装、政策或流程:门禁、打包、发版. 不属于运行时行为. |
| \`testing\` | 测试基础设施与测试策略. |

## 用来判近似情形的边界

- **\`architecture\` vs \`process\`** —— architecture 是你交付的源码;process 是围着它的工装. 「会话日志是仅追加的 JSONL」是 architecture.「日志由一个 pre-push 门禁校验」是 process.
- **\`refactor\` 是刻意没有的.** 它的判据本来就是「可观察行为变没变?」—— 变了就归 \`feature\`、\`bug-fix\` 或 \`architecture\`;没变就是 \`simplification\`.
- **\`feature\` 不只给新能力.** 一个对用户或下游消费方可观察到的行为或产品选择,就算代码改动很小也归这里. **判据是可观察性,不是 diff 大小.**
- **\`simplification\` 必须写明它的上限.** 它的 \`## Consequences\` 要写清这次删除付出了什么代价、以及**什么信号出现时应该重新考虑**. 一条没写升级触发条件的简化,会悄无声息地变成永久决定.

## 什么时候不需要 note

纯机械或局部改动:格式化、注释里改个错字、无行为变化的锁文件升级、打 tag. 如果保护这类情形仍然让你觉得不对,覆盖率门禁的 \`NOTE-EXEMPT.md\` 逃生舱会**把这个人肉判断记录下来,而不是藏起来**.

## 脚本查不了的语义义务

门禁能验证一个章节存在,但验证不了它是诚实的:

- \`Alternatives\` 的每一条都先陈述了对手最强的论据再驳回,并且至少有一档是「什么都不做,或复用已有的」.
- 任何验证性声明都落在**可查的面上** —— 哪条路径、多大数量级、哪条命令. 没有基线的「更快」「更小」是未经验证的断言,比不给声明更糟.
- \`Consequences\` 既承载被放弃的,也承载换来的.
