# 生命周期:保留、归档、删除

这里没有任何东西是按字数或年头来判断的. 唯一的问题是:**这份记录还能不能拦住一个未来的错误.**

## 只要满足条件,再旧也保留在 active

只要满足以下任一条,一篇 implemented note 就留在 `implemented/`:

- 它设定了一条归属边界(「UI 层永远不直接跟数据库说话」).
- 它陈述了一条否定性保证(「我们永远不会支持协议 X」).
- 它记录了一条安全或合规约束.
- 它记录了一个诱人但已被证明失败的备选,而**诱惑仍在**.
- 它写明了这条决策在什么条件下应该被重新审视.

## 归档

当已落地的决策已经完成、且它的理由不太可能再指导后续工作时归档:一次性的 UI 装饰、为已退役平台写的窄适配器、一个已关闭的小 bug、以及当前行为从代码里一眼可见的流程历史. 用下面的命令移动:

```sh
npx tsx <skill>/scripts/archive-note.ts .agents/notes/implemented/<class>/<file>.md
```

脚本会把文件移到 `archived/<class>/`(注意 `implemented` 那一段是刻意去掉的),在 `Status: implemented` 行下面插入 `Archived: YYYY-MM-DD`,报告**每一条**入站引用 —— 其他 note 和源码引用一视同仁 —— 并重新封装 manifest. 把每条引用重定向到归档路径,或者指向现在拥有这条决策的 note;**留在那里悬空的,反向引用门禁会判失败**. 正文其他任何内容都不许改. Seal 之后该文件即冻结:**永不编辑、重排版、翻译或移动它**,也永不把它当作当前行为的权威. 文档类门禁会跳过归档 note,包括它们的外链;active 正文在被刻意引用历史时,仍然可以链进去.

## 用删除代替归档

- **不打算推进的 `proposed/` note** 转为 `rejected/`;当连那句判决都不值得留时,直接删除. **提案永远不归档.**
- **前提已经消失的 `rejected/` note** —— API 被删了、技术被淘汰了、问题在别处已经定了 —— 连同它的对照件一起直接删除. 一条防着"如今没人犯得出来的错"的护栏,只会稀释那些仍然重要的护栏.

## 取代与合并

一篇被完全取代的 implemented note,可以在新 note **完整保留了旧 note 每一条独有的理由、备选、后果与反转**,且所有入站链接在同一次改动里修复的前提下,被合并进后继者并删除.

这个合并只有在旧决策**真的已经消失**时才成立:不再出现在生产代码、配置、schema、持久化或线上格式、迁移、以及兼容行为里;没有被文档描述为可用;也没有被任何测试当作受支持的行为来跑. **一条仍然活在持久化格式或兼容垫片里的决策,只是被部分取代 —— 两篇都要留,互相链接.** 而这恰恰是常态:归档区保住了「这个垫片为什么还在?」的答案,而那个问题问出来的下一步,就是把它错误地删掉.

## 什么时候该做全量体检

**90% 的工作都是顺手的**:更新你正在改的那段代码所附带的 note,并在取代它的同一次改动里归档旧的.

全库审阅是**里程碑活动,不是常规动作** —— 季度复盘、大版本,或者一棵已经大到"浏览它不再便宜"的活跃目录树. 做的时候按[全库审计](quality-gate.md#全库审计)来,读遍范围内每一篇,而且**永远不要对着一个目标数量去做**.
