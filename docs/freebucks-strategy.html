Freebuff 的计费策略：一次 admit = 买断一小时

别管"退款"这个词——它按小时卖，早退不等于退钱。本图全部数字为一手实测。

最优解：不要早退。已经付过的那一小时，用满它。

同一小时内第 2 次提问，边际成本是 0。 一旦 DELETE，那一小时就作废，重开 = 重新买一整小时。

22 / 24 都是 Freebucks 先见底。 而早退只把 units 退回来 —— 我们等于在拿稀缺的账去省不稀缺的账。

5落到代码上：只改一件事

现在

idle_release_sec = 60
空闲 60 秒 → DELETE。流量有间隔就疯狂重复买。

已改成

已付费时长内不释放
保留到 expiresAt；只在必须腾槽位给别的模型时才早退。

落地位置：

  • session-manager.paidWindowRemainingMs() / inPaidWindow()：付费时段判定（fail-open）
  • _armIdleRelease()：时段内直接清计时器、不释放；idle_release_sec 变成"时段结束之后"的释放时长
  • 控制台 classifyAccount()：付费时段内 rem=0 判为可用，不再误报「额度不足」
  • 测试：smoke 用例 1 双向钉死（时段内 0 次 DELETE；过期后恢复释放）

代价（说清楚，不是白赚）：

  • 一个账号同时只能有 1 条 session 且绑定模型，hold 住这一小时，别的模型这一小时用不了这个号
  • 所以并发多模型时要靠账号池分散，而不是靠频繁释放腾位置
  • 顺带好处：admit 次数大幅下降 → 上游眼中更不像"轮换账号的农场"

一句话：把那一小时当成已经买到手、会过期的资产—— 该做的不是"暂停后恢复"，而是根本别暂停。
